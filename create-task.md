# Create task

## Actor
Клиент (Браузер)

## Predictions
Авторизация пока не входит в объём проекта. Пользователь может открыть форму создания задания. У пользователя есть право добавления задания в базу данных.

## Main flow
1) Запрос от клиента на создание/изменение базы данных:
```http
POST /tasks HTTP/1.1
Host: UTT.example.com
Content-Type: application/json
```
```json
{
  "title": "Лабораторная работа № 1",
  "status": "in_progress",
}
```

2) Проверка и применение изменений/ответ, запрашиваемый клиентом

3) Ответ сервера запрос клиента:
```http
HTTP/1.1 201 ACCEPTED
Content-Type: application/json
```
```json
{
  "id": "271"
  "title": "Лабораторная работа № 1",
  "status": "in_progress",
}
```

## Alternative flows
### Empty title
При пустом названии, сервер:
1) Возвращает ошибку, а интерфейс просит клиента задать название
2) Автоматически даёт объекту (работе/заданию) имя "Untitled #N"

### invalid due date
При неверном формате даты (пример: DD/MM/YYYY вместо YYYY/MM/DD), выдаст ошибку "invalid date format". (пример верного формата изначально будет в строке ввода)
При указании несуществующей даты, вернёт ошибку "invalid date"
При указании прошедшей даты, интерфейс создаст задание в базе данных, но сразу со статусом "status:" "overdue"
